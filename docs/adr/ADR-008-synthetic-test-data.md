# ADR-008. Синтетические данные и изоляция тестовых прогонов

- **Статус:** рабочая гипотеза для учебной архитектуры, неделя 10
- **Связи:** [стратегия качества](../quality/10-quality-strategy.md), NFR-02/03/04, DQ-01…06, T-09

## Контекст

Для регрессии требуются связные данные заявок, ролей, резервов и событий. Редкими состояниями — подтверждённым резервом с потерянным ответом, повтором события и недоступностью зависимости — нужно управлять из теста. Контакты и свободные описания из продуктивной системы создают риск раскрытия.

## Варианты

| Вариант | Воспроизводимость | Защита данных | Затраты |
|---|---|---|---|
| Маскированная копия | Снимок меняется; редкие состояния требуется готовить | Остаточный риск раскрытия через связи и текст | Маскирование и постоянная проверка выгрузок |
| Общие ручные фикстуры на stage | Сценарии конфликтуют при изменениях и параллельном прогоне | Можно создать полностью синтетический набор | Поддержка состояния общей среды |
| Сценарные фабрики с seed и изоляцией | Версионируемые входы, редкие случаи по запросу | Синтетические идентификаторы, контакты и тексты | Генератор и обслуживание эмуляторов |

## Решение

Выбрать сценарные фабрики с seed и изоляцией. Использовать уникальный контекст набора на прогон и управляемые часы, создавать связанные записи в порядке зависимостей, сохранять seed и ID прогона в отчёте. Запускать совместимость адаптеров в песочницах при наличии; задержки и ошибки воспроизводить в эмуляторах по контрактам. Для нагрузки генерировать расчётный объём заявок и типовые распределения статусов, затем уточнить их по обезличенным агрегатам пилота.

## Последствия и проверка

Регрессия повторяется с тем же seed, параллельные тесты не читают данные друг друга, тестовые контакты попадают только в тестовый приёмник. Потребуется обновлять фабрики и эмуляторы вместе с контрактами. Приёмка решения включает два параллельных прогона с одним seed, проверку DQ связей и полноты, проверку отсутствия производственных секретов и успешное воспроизведение задержки/ошибки каждого эмулятора. Решение пересматривается, если синтетический профиль перестаёт воспроизводить выявленный пилотный дефект.
