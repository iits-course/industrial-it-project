# Реестр ADR

Architecture Decision Records модуля 2. Формат: Nygard, дополненный матрицей альтернатив (занятие 5). Принятый ADR не переписывается: изменение решения оформляется новым файлом со ссылкой на заменённый.

| ID | Решение | Статус | Драйверы | Элементы C2 |
|---|---|---|---|---|
| [ADR-001](0001-architectural-style.md) | Модульный монолит | Рабочая гипотеза v0.1 | Размер команды, инвариант заявки, NFR-02…04 | Приложение РемКонтур, АРМ, обработчик исходящих, БД заявок |
| [ADR-002](0002-database.md) | PostgreSQL как система записи | Рабочая гипотеза v0.1 | Транзакции, идемпотентность, аудит, NFR-03 | БД заявок |
| [ADR-003](0003-messaging.md) | Без брокера: transactional outbox | **Заменён [ADR-004](ADR-004-message-broker-rabbitmq.md)** | Уведомления, изоляция внешнего сбоя, стоимость эксплуатации | Обработчик исходящих, таблица outbox в БД заявок |
| [ADR-001 · аналитика](ADR-001-analytics-delivery.md) | Доменные события из outbox в аналитику, bootstrap-выгрузка (неделя 6) | Принято для учебной архитектуры | Изоляция OLTP, свежесть ≤ 15 мин, NFR-03 | Analytics Loader, Warehouse |
| [ADR-002 · сага](ADR-002-assignment-saga-orchestration.md) | Оркестрация саги назначения (неделя 7) | Принято для учебной архитектуры | FR-04, FR-06, NFR-02, NFR-04 | Приложение, Workforce Service |
| [ADR-004](ADR-004-message-broker-rabbitmq.md) | RabbitMQ вместо «без брокера» (неделя 8) | Рабочая гипотеза v0.2, заменяет ADR-003 | Два независимых потребителя, контракты AsyncAPI, владение данными | Outbox Relay, RabbitMQ, потребители |
| [ADR-005](ADR-005-notification-channel-adapter.md) | Канал уведомлений за адаптером, план выхода (неделя 8) | Рабочая гипотеза v0.2 | Lock-in, изоляция сбоев, замена провайдера | Notification Worker, Адаптер уведомлений |
| [ADR-006](ADR-006-external-boundary-acl.md) | ACL выборочно, в чужие БД не пишем (неделя 8) | Рабочая гипотеза v0.2 | Ограничения legacy, NFR-02, NFR-03, NFR-04 | Master Data Adapter, Адаптер уведомлений, `access-audit` |

Номера ADR-001 и ADR-002 использованы дважды: файлы `0001`, `0002` (неделя 5) и `ADR-001-…`, `ADR-002-…` (недели 6–7). Различайте их по файлам; новые решения нумеруются с ADR-004.

Клиентская очередь создания заявки описана в [TS-01](../04-technical-spike.md) и [NFR-02](../04-requirements.md); отдельный ADR на брокер для офлайн-режима не нужен, пока очередь живёт в АРМ.
