# Неделя 10 · Требование → тест → метрика

Пороги NFR и DQ перенесены из [реестра требований](../04-requirements.md) и [карточек качества данных](../data/06-oltp-olap-quality-lineage.md). Пороги для угроз и доступа ниже — рабочие критерии разбора. Метрики описывают целевое наблюдение; базовые значения пилота отсутствуют.

| Источник | Проверка и критерий | Метрика и реакция |
|---|---|---|
| FR-01, NFR-01 | E2E-01, QA-01, пилотная выборка со временем обнаружения | Доля штатных заявок за ≤ 10 мин от обнаружения, отдельно доля заявок без достоверного времени; владелец процесса уточняет источник начала |
| FR-02 | Компонентная проверка AC-02: похожая заявка даёт предупреждение, разрешённое продолжение сохраняется | Доля показанных предупреждений и решений продолжить; диспетчер разбирает найденные дубли |
| FR-03 | E2E-01/04 и A-02: карточка, согласованная история и доступ по роли | Доля ошибок чтения карточек и несоответствий истории; Martin разбирает отклонения |
| FR-04 | E2E-02/03: единственный резерв и подтверждённое назначение | Доля саг по исходам и время до назначения; Andrey разбирает затянувшиеся саги |
| FR-05/06/07 | E2E-04: переходы, автор и результат в данных | Число закрытий без результата и изменений приоритета без автора/причины; любое нарушение требует разбора |
| NFR-02 | QA-02, E2E-01: окно 4 ч, 50 повторов на сценарий, 0 потерь, ≤ 1 заявка на операцию, синхронизация за ≤ 60 с после восстановления | Возраст старейшей записи очереди, время от восстановления до подтверждения, число потерянных/дублированных операций при сверке; Martin разбирает выход за рабочие пороги |
| NFR-03 | QA-03, нагрузка по §6.5, p95 ≤ 2 с отдельно по трём экранам | p95 списка, карточки и формы по клиентским замерам; при превышении по экрану владелец АРМ проверяет зависимость и профиль нагрузки |
| NFR-04, A-01…A-11 | QA-04: компонентный/интеграционный набор по каждой строке и субъекту; разрешения проходят, запреты отклоняются, есть аудит | Отказы по операции и политике, доля отказов с записью аудита и число подтверждённых нарушений политики; пропуски или нарушения разбирает ИБ |
| DQ-01 | Модульные и API-проверки обязательных полей, E2E-01 | Доля полных новых заявок 100%; нарушение направить владельцу данных |
| DQ-02 | Модульная таблица переходов и E2E-04 | Доля допустимых переходов 100%; нарушение разбирает владелец домена |
| DQ-03 | Интеграционная проверка ссылок и возраста проекции, E2E-01 | 100% валидных новых ссылок; возраст проекции и число регистраций по устаревшим данным; при > 60 мин steward получает предупреждение. Для известного оборудования тестируется предложенное исключение недели 8, ожидающее согласования с владельцем DQ-03 |
| DQ-04, T-02 | Интеграционная проверка ключа и версии, E2E-01/02 | Дубли заявок на операцию и активных назначений: 0; нарушение — инцидент |
| DQ-05 | E2E-03/04 и сверка событий назначения и выполнения по версии и окну | Расхождение после 15 мин: 0; отстающая витрина помечается как неполная |
| DQ-06 | E2E-03: задержка и догон потока | ≥ 99% событий в витрине за ≤ 15 мин по суточному окну; критические догружаются ≤ 60 мин после восстановления |
| T-01, T-04 | Компонентный SSO: доверенный access token проходит, истёкший или с неверными issuer/audience отклоняется | Причины отказа аутентификации и сбои обновления JWKS; всплеск разбирает ИБ |
| T-03 | Компонентные A-03/04, E2E-02 вне области, интеграционная проверка утраты полномочий до pivot с компенсацией резерва | Число подтверждённых назначений вне политики: 0; отказы и отмены по причине утраты полномочий наблюдаемы |
| T-05 | Интеграционная A-08: разрешённый клиент и scope, запрет чужого резерва и запрет для иной идентичности | Отказы Workforce по клиенту и scope; неожиданные отказы или успехи вне политики разбирают Andrey и ИБ |
| T-06 | E2E-02: таймаут, сверка по saga ID и неуспешная компенсация | Доля таймаутов, время сверки, число `failed_manual_review`; ручная очередь у Andrey |
| T-07, T-08 | Интеграционный тест прав брокера и E2E-03: дубль и недоступность | Возраст старейшей записи outbox, повторная обработка, дубли эффектов: 0; Amir разбирает задержки и дубли |
| T-09 | Контрактный тест разрешённых полей уведомления и компонентная проверка минимизации диагностики | Число нарушений схемы и подтверждённых раскрытий: 0; нарушение разбирают Amir и ИБ |
| T-10 | Интеграционный тест записи с commit, отказа буфера, повтора доставки и неизменяемости журнала; оракулы E2E-02/04 | Доля операций с обязательным аудитом, возраст буфера и ошибки записи; пропуск расследует ИБ |

Для A-01…A-11 данные проверки включают разрешённую роль с выполненными условиями, ту же роль вне области или допустимого состояния и остальные роли с запретом. Сервисные строки проверяются со своей идентичностью и отдельно с неверным scope или чужим ресурсом. Статусные и предусловные ошибки проверяются по контракту; отказ в полномочии проверяется отдельным случаем. Для каждой ветки проверяются отсутствие запрещённых изменений и аудируемость отказа.

Перед взаимным ревью пройти по каждой цепочке «угроза → контроль → оракул → метрика» и разобрать минимум один отказ внешней зависимости до конца. Зафиксировать замечания и владельцев после фактического ревью.
